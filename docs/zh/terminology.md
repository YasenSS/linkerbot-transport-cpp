# 术语与可观测行为

[文档索引](../README.md) · [English](../en/terminology.md)

指南、注释和问题报告统一使用以下定义。

- **后端接受（backend acceptance）**：按相应后端语义成功返回的 `write()` 或原生批次调用，不表示 CAN 确认或设备执行完成。
- **CAN 确认（ACK）**：CAN 数据链路层确认，不标识预期的应用设备，也不确认设备执行了命令。
- **串口确认（serial acknowledgment）**：固件对串口命令或帧的响应。Lawicel 与 CANable 的响应行为不同，见 [SLCAN](slcan.md)。
- **业务回复／业务确认（application reply / business confirmation）**：由上层设备协议解析并关联的响应。本通信库不实现这种关联。
- **发送回执（send receipt）**：一个调度批次的软件状态。`dispatched` 表示所有帧已被后端接受；失败或超时的操作仍可能送达部分帧。
- **接收超时（receive timeout）**：接收等待期间未返回应用帧，不能单凭此结果认定断连。
- **等待超时（wait timeout）**：调用者停止等待回执，不取消调度任务或在途驱动调用。
- **截止时间（deadline）**：基于 `std::chrono::steady_clock` 的绝对时刻，不是 UTC 时间戳，也不是不可中断驱动调用的硬性时限。
- **恢复（recovery）**：显式尝试重建具备恢复条件的连接。成功后更新代次并使旧 inbox 失效，不重放命令，也不核验设备身份。
- **代次（generation）**：区分进程内连接／会话状态的标记，不是持久设备标识或命令序号。
- **延迟清理（deferred cleanup）**：在进程内保留资源归属，供后续释放，不是持久队列或恢复日志。
- **幂等关闭（idempotent close）**：成功清理后重复调用关闭是安全的。清理失败可能保留资源并需要重试，不表示每次调用都一定成功。
- **离线回归／测试替身（offline regression / fixture）**：使用内存、伪终端、socket pair 或测试动态库的验证，不构成实机验收。
- **支持目标（supported target）**：平台／后端的实现目标。**验证结果（verified result）**对应指定提交、工具链和测试运行；两者都不表示已经测试所有适配器、驱动和固件组合。

描述测量值时应明确范围：生产代码汇总行覆盖率、逐文件覆盖率、分支覆盖率和实机验收不同；速率应注明是载荷字节还是线上流量，配置的超时预算应与实测延迟区分。

两种语言保持 API 标识符一致，只翻译解释，不翻译枚举项、错误码、环境变量或命令。行为因后端而异时，须写明后端和模式，不能将一个后端的默认行为推广到整个库。
